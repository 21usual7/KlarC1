# Klar C1

Тренажёр профессиональной лексики немецкого (информатика, кибербезопасность, математика) — дополнение к основному курсу для будущей учёбы в Вене. Next.js App Router, TypeScript, React, CSS и Lucide. Исходное задание: `prompt.txt`.

## Запуск

Требуется Node.js 22.18+ (рекомендуется 24 LTS), npm и доступ к npm registry.

```sh
npm install
npm run dev
```

Открыть http://localhost:3000. Для production: `npm run build`, затем `npm start`.

Для тьютора скопировать `.env.example` в `.env.local`, заполнить `GEMINI_API_KEY` (бесплатный ключ: https://aistudio.google.com/apikey) или `OPENAI_API_KEY`, при необходимости `GEMINI_MODEL` / `OPENAI_MODEL`. Если задан `GEMINI_API_KEY`, используется Gemini, перезапустить сервер. Ключ используется только серверным маршрутом. Не коммитить `.env.local`.

## Что реализовано

- Главная `/` проверяет серверную сессию: без входа показывает гостевую страницу с описанием платформы, примером занятия и ссылками на вход/регистрацию; после входа — учебный кабинет. Сохранённая ранее гостевая работа остаётся в браузере и доступна для переноса в новый аккаунт.
- Стартовый обзор, onboarding: имя, направление, уровень, целевой экзамен и дата.
- Восемь авторских вопросов для предварительного определения A1–B2. Это не сертифицированный placement test; C1 не присваивается.
- **Тренажёр лексики** (подробно: [docs/vocab-trainer.md](docs/vocab-trainer.md)): 3 сферы × 3 уровня (A1.2, A2.1, A2.2) = 9 модулей по 16 слов. Модуль — два урока по 8 слов и тест. У каждого слова карточка с картинкой (иконка Lucide).
- Урок 15–20 минут: блок из 4 слов → карточки → круг «узнать» (аудирование, значение) → «вспомнить» (найти слово, артикль, композит, пропуск с вариантами, мн. число) → «использовать» (пропуск без подсказки, перевод сочетания, диктант, собрать предложение) → следующий блок → финальный смешанный круг → текст на лексике урока (перевод слова по наведению/нажатию) → вопросы на понимание → перевод предложений в обе стороны. Ошибка возвращает слово в конец круга (не более 2 раз). В конце — своё предложение с проверкой через ИИ-тьютора.
- Повторение по FSRS (`ts-fsrs`): урок без ошибок → через 2 дня, с ошибками → завтра, ошибка в повторении → через 10 минут. Стадии слова: Узнаю → Вспоминаю → Использую → Выучено. Тест модуля — 16 слов без вторых попыток, зачёт от 80 %.
- Сохранение профиля, сферы, стадий слов, FSRS-карточек, пройденных уроков, тестов и журнала в Cloudflare D1 после входа; без входа — в гостевом профиле браузера. Старые сохранения историй мигрируются: профиль, самооценка и журнал остаются, черновики историй удаляются.
- Radar и редактируемая самооценка шести навыков, журнал, вехи. Нет вымышленных баллов или результатов экзамена.
- Интерфейс тьютора с четырьмя ролями и работающим серверным маршрутом Gemini/OpenAI при наличии ключа. В запрос включаются последние 12 реплик с общим ограничением истории 16000 символов. История сохраняется в браузере; смена роли начинает новый разговор. Без ключа показывается честное сообщение об отсутствии интеграции.
- Адаптивный интерфейс, управление модальными окнами с клавиатуры, поддержка reduced motion.

## Ограничения и следующий этап

Это первый прототип, а не завершённая платформа. Есть email/password-регистрация, cookie-сессии, Cloudflare D1 и синхронизация устройств. Нет PWA/offline-кеша, распознавания/оценки речи, календаря, экзаменационных симуляций или адаптивной диагностики. Озвучивание зависит от установленного немецкого голоса браузера; шрифты Google необязательны, есть системные fallback-шрифты. Сервер тьютора ограничивает обращения по IP; перед публичным размещением дополнительно нужны политика доступа и ограничения бюджета провайдера.

Тексты авторские, не официальные материалы TU Wien. Требования и методические основания проверены отдельно: [исследование и источники](docs/research.md), [учебная методика A1–C1](docs/methodology.md). A1 — старт обучения; для рассмотренного пути подачи с иностранным аттестатом нужны признанный A2 и затем C1 к началу основной учёбы. Для уже зачисленных в VWU действует отдельная экзаменационная развилка. Условия конкретной программы: https://www.tuwien.at/en/studies/admission.

Архитектура и план развития: [docs/architecture.md](docs/architecture.md).

## Уточнённый учебный фокус

Приоритет — математика и криптография, информатика и кибербезопасность. Рассматриваются бакалавриат и магистратура; выбор сохраняется в профиле и передаётся тьютору. Темы будущих модулей зависят от фокуса. Базовые занятия остаются доступными на A1. Проверенные варианты программ и границы персонализации: [docs/study-targets.md](docs/study-targets.md).


## Тьютор, домашние задания и аккаунты

- Gemini получает контекст диалога, уровень, выбранный предметный фокус и ступень обучения. При 429/503 или таймауте пробуется следующая настроенная модель, без переключения на платный OpenAI, если выбран Gemini. Лимиты и доступность бесплатного тарифа зависят от Google.
- Домашние задания A1–C1: авторское задание по уровню, необязательные опоры, черновик, AI-проверка, исправление и история попыток. Тьютор получает исходное задание с сервера и прошлые попытки. Оценка AI не является сертификатом CEFR.
- Кнопки чтения слов/фраз используют локальные немецкие голоса браузера, есть медленный режим. При отсутствии голоса показывается объяснение. Микрофон и автоматическая оценка произношения не подключены. План развития: [docs/voice-homework.md](docs/voice-homework.md).
- Регистрация/вход/выход доступны через «Аккаунт». При заполненной конфигурации D1 пользователи и сессии хранятся в облаке. Пароли хэшируются scrypt с индивидуальной солью, session token передаётся HttpOnly/SameSite cookie, в базе только хэш токена. Email подтверждается одноразовой ссылкой через Resend; без подтверждения вход закрыт. Пароль можно сбросить со страницы входа по одноразовой ссылке из письма.
- Прогресс, чат и домашние задания привязаны к user_id и сохраняются в D1 через сервер, с резервным кешем браузера отдельно для каждого аккаунта. Загрузка при входе, обновлении страницы/возврате в окно и по кнопке «Обновить». На время сетевого запроса действует индикатор сохранения; ошибки видны и доступны повторная отправка/экспорт.
- При конфликте версий на разных устройствах запись не перезаписывается: можно скачать локальную копию и загрузить облачную. Автоматическая резервная копия конфликтной локальной версии также остаётся в localStorage.
- Гостевые данные не присваиваются аккаунту автоматически. После входа в пустой облачный профиль доступна кнопка переноса гостевой работы. Исходные старые ключи localStorage не удаляются. При выходе снова открыт отдельный гостевой профиль.
- При полной или частично заданной конфигурации D1 ошибка облака не переключает авторизацию на локальный файл. Файловая реализация оставлена для unit tests и импорта старых данных; публичные API авторизации требуют D1 и не переключаются на файл. Перед публичным размещением ещё нужны ограничения общего бюджета AI.


Проверки: 17 unit tests, TypeScript, production build. Живые запросы Gemini проверены для беседы и коррекции домашнего задания. Браузерный сценарий домашних использует тестовые AI-ответы, чтобы не расходовать квоту на повторных прогонах.


## Настройка D1 и миграция

В `.env.local` (никогда не коммитить): `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_D1_DATABASE_ID`. Сервер Next.js обращается к официальному D1 REST API; браузер никогда не получает Cloudflare token. Для обычной работы токену нужны соответствующие права D1 Read/Write. При reverse proxy можно явно задать `APP_ORIGIN=https://ваш-домен` для проверки Origin.

```sh
node --experimental-strip-types scripts/setup-d1.mjs
node scripts/migrate-auth.mjs
npm run dev
```

Схема `migrations/0001_accounts_and_learning.sql` применяет только `CREATE IF NOT EXISTS`. Миграция переносит существующих локальных пользователей с ID/хэшами паролей и активные сессии, сохраняя `.data/auth.json`. При конфликте ID/email останавливается, не перезаписывает D1. Повторно запускать импорт существующих аккаунтов без проверки нельзя. Если файла нет, переносить нечего.

Таблицы: `users`, `sessions`, `learning_state`. Учебное состояние сохраняется JSON-документом с revision и user_id; это первый вариант схемы, а не построчная аналитическая модель. Ограничение одного сохранения API — 1 МБ. Сервер проверяет сессию для каждой записи, игнорирует переданный извне user_id и использует сравнение revision для защиты от конфликтов. REST API Cloudflare имеет собственные ограничения частоты, поэтому запись выполняется с задержкой после редактирования, не на каждый символ.

Живой интеграционный прогон D1 проверил регистрацию/вход, cookie, перенос гостевой работы, прогресс/чат/домашние на двух независимых браузерных профилях, изоляцию аккаунтов, 401 без входа, 409 при устаревшей версии и отзыв сессии. Созданные для проверки аккаунты удалены по их точным ID.


## Отдельные страницы и подтверждение email

- `/login` — вход; `/register` — регистрация; `/verify-email` — подтверждение из письма. Авторизация больше не открывается модальным окном.
- Новые регистрации создают неподтверждённый аккаунт без cookie-сессии. До подтверждения вход возвращает403 `EMAIL_NOT_VERIFIED`. Существующие аккаунты без отметки подтверждения также должны подтвердить email; их учебные данные не удаляются.
- Письмо отправляется через Resend (`https://resend.com/docs/api-reference/emails/send-email`). Нужны `RESEND_API_KEY`, `EMAIL_FROM` и правильный `APP_ORIGIN`. Для отправки произвольным адресатам нужен подтверждённый домен отправителя в Resend; возможности тестового отправителя ограничены провайдером. Ключи только в `.env.local`/секретах сервера.
- В текущем окружении почтового ключа нет. Реальная доставка не настроена: API возвращает `emailDelivery: not_configured`, UI честно сообщает, что аккаунт создан, но письмо не отправлено. Ни ссылка, ни код не выдаются браузеру как отладочный обход подтверждения.
- Токен — 32 случайных байта, срок24часа, в D1 только SHA256. Ссылка передаёт секрет во фрагменте `#token=`, чтобы он не попадал в HTTP access logs. GET/открытие страницы ничего не подтверждает: нужен явный POST по кнопке. Повторное использование отклоняется. После подтверждения нужно войти с паролем.
- Повторная отправка ограничена в D1: минимум60секунд и не больше5писем в час для аккаунта. Сбой доставки не подтверждает email и не создаёт сессию.
- Миграция `0002_email_verification.sql` добавляет nullable email_verified_at, токены и лимиты. `scripts/setup-d1.mjs` применяет её после базовой схемы; отдельно можно запустить `node --experimental-strip-types scripts/setup-email-verification.mjs`.
- Тесты проверяют отсутствующую доставку, ошибки провайдера, блокировку входа, хэш токена, истечение, одноразовость/гонку двух подтверждений, cooldown и доступ после подтверждения. Живой D1-прогон использовал код-фикстуру только для синтетического тестового аккаунта, а не реальную доставку. Тестовый аккаунт удалён. Подмена провайдера применяется только в тестах, не в коде приложения.


## Серверный лимит тьютора

`/api/tutor` допускает 100 обращений с одного IP за календарный день UTC (сброс в 00:00 UTC). Чат и проверка домашних делят квоту, Gemini и резервный OpenAI используют один счётчик. Один входящий запрос резервирует одно обращение до вызова AI; повторные попытки моделей внутри него не считаются отдельными обращениями. Неудачные вызовы также расходуют обращение. Некорректные запросы не учитываются.

Исключение: вошедший пользователь с подтверждённым email `21usaul7@gmail.com`. Серверная переменная `AI_ADMIN_EMAILS` позволяет переопределить список (через запятую); пустое значение отключает исключения. Email из тела запроса или произвольных заголовков не даёт исключений. Запросы администратора не расходуют квоту общего IP.

Квота хранится в D1 (`migrations/0003_ai_request_limits.sql`), резервирование атомарное. Миграция включена в `scripts/setup-d1.mjs`; для существующей базы: `node --experimental-strip-types scripts/setup-ai-request-limits.mjs`. Сырые IP не сохраняются, ключ — SHA-256 от нормализованного адреса; устаревшие дневные записи удаляются. Сбой счётчика блокирует вызов AI.

Используйте `npm run dev` / `npm start`: `scripts/server.mjs` получает IP из TCP-соединения и подписывает внутренний заголовок случайным секретом процесса. Прямой запуск `next dev` / `next start` не поддерживает получение доверенного IP, запросы обычных пользователей к AI будут отклоняться. Подделанный клиентом `X-Forwarded-For` по умолчанию игнорируется. Если перед Node стоит обратный прокси, задайте его точные адреса в `AI_TRUSTED_PROXY_IPS` (через запятую); прокси должен добавлять реальный адрес клиента справа в `X-Forwarded-For` либо полностью перезаписывать этот заголовок. Цепочка разбирается справа до первого недоверенного адреса. Доступ к доверенным прокси должен соответствовать этой конфигурации.

В интерфейсе нет счётчика и сведений о квоте. При исчерпании возвращается HTTP 503 с обычным сообщением о временной недоступности тьютора, без чисел, времени сброса или специальных заголовков квоты. Уже существующая ошибка квоты самого AI-провайдера обрабатывается отдельно.


## Профиль, рейтинг и сброс пароля

- На странице `/profile` можно изменить имя аккаунта и учебный план, посмотреть достижения и включить участие в рейтинге. Рейтинг показывает имя и очки только участников, которые включили эту настройку.
- Таблица `scoreboard` в D1 обновляется при сохранении учебного прогресса. При включении участия учитывается уже сохранённый прогресс. Каждый завершённый урок даёт 10 очков, каждый сданный тест модуля — 30. `/scoreboard` показывает до 50 участников и твоё место.
- Сброс пароля доступен для подтверждённых адресов. Нужны `RESEND_API_KEY`, `EMAIL_FROM` и `APP_ORIGIN`. Последняя ссылка действует 30 минут. После смены пароля все сессии аккаунта завершаются.
- Удаление требует подтверждения последствий, слова «УДАЛИТЬ» и текущего пароля. D1 удаляет связанные с аккаунтом данные каскадно. Кэш аккаунта очищается в браузере, где запросили удаление.

Миграция включена в `scripts/setup-d1.mjs`. Для существующей базы её можно применить отдельно:

```sh
node --experimental-strip-types scripts/setup-profiles.mjs
```
