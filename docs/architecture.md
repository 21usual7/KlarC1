# Архитектура первого прототипа

## Информационная архитектура

Обзор → настройка цели → предварительная диагностика → персональный профиль → маршрут → Deep Session → повторение → прогресс.

Обзор служит стартовым экраном и кратко объясняет подход. В маршруте четыре ступени: первые шаги (A1–A2), Foundation (A2–B1), Solid Intermediate (B1–B2), Academic & Exam Ready (B2–C1). Доступны начальная сессия A1 «Hallo, Wien!» и сессия A2–B1 «Dein erster Tag in Wien». Остальной контент явно помечен как находящийся в разработке.

В Deep Session последовательный flow: Warm-up → Input → Guided Practice → Output → Review → Reflection. Переход к продуктивному этапу требует проверки всех вопросов. Объём письма зависит от уровня и служит ориентиром: A1 — 25–50 слов с опорами; A2–B1 — 80–120 слов. Для перехода нужен непустой ответ, жёсткий порог объёма убран. Устный пересказ пока самостоятельный и не оценивается автоматически. После завершения создаётся артефакт с датой, временем таймера и самооценкой; словарь попадает в очередь повторения. Прочтение текста и устное выполнение основаны на действиях самого ученика, не на автоматическом контроле.

Focus Mode сохраняет учебный контекст и убирает навигацию. Для A1 доступен таймер 20 минут с паузой; 45–90 минут не являются обязательным педагогическим нормативом. Таймер использует дедлайн по реальному времени, чтобы переключение вкладок не замедляло обратный отсчёт. Пауза исключается из длительности. Выход из полноэкранного режима не сбрасывает данные.

## Разделение ответственности

- `src/app/page.tsx`, `layout.tsx`: вход и метаданные приложения.
- `src/components/klar-app.tsx`: адаптивная оболочка, навигация и состояния учебного flow. На следующем этапе разделить по компонентам экранов и выделить store.
- `src/lib/learning.ts`: учебный контент, типы, оценка скрининга, интервалы и создание результата. Чистые функции отделены от UI и проверяются тестами.
- `src/app/api/tutor/route.ts`: серверная граница OpenAI, проверка ввода, ограничения размера, таймаут, скрытый ключ, понятные ошибки. Пользователь выбирает только разрешённую роль.
- `src/app/globals.css`: визуальные токены, компоненты и адаптивная раскладка.

Сейчас источник данных — localStorage (`klar-c1-v1`). Загрузчик валидирует сохранённые поля и мигрирует старые записи; черновики A1 и A2–B1 хранятся раздельно и восстанавливаются при смене уровня. Результаты и карточки привязаны к выбранному модулю. Это сознательное ограничение локального прототипа: приложение не утверждает, что данные синхронизируются с аккаунтом.

## План серверной модели

PostgreSQL + Prisma, авторизация email/Google через Auth.js или Supabase Auth. Сущности:

| Сущность | Назначение |
| --- | --- |
| User / LearnerProfile | Аккаунт, направление, цель, даты |
| PlacementAttempt / SkillAssessment | Источник оценки, версия теста, результаты по навыкам |
| Module / SessionStage / ContentVersion | Версионируемый контент и требования к этапам |
| SessionAttempt / Artifact | Несколько попыток, письменные и устные результаты |
| ReviewCard / ReviewEvent | Происхождение карточки и история повторений |
| TutorConversation / TutorMessage | Контекст беседы, согласие, стоимость |
| ExamPlan / Checkpoint | Нагрузка, вехи и результаты checkpoint-тестов |

При миграции импортировать localStorage после входа, с дедупликацией по локальным ID. Данные пользователей изолировать по user_id; записи проверять сервером. Ключи провайдеров хранить в серверных переменных окружения. До публичного доступа к AI добавить авторизацию, rate limiting и лимит стоимости на пользователя.

## Следующие вертикальные срезы

1. Проверить текущие требования TU Wien и целевой программы по официальным страницам. Отдельно разобрать официальные модели принимаемых экзаменов и правила использования материалов. Не смешивать поступление, знание языка и Aufnahmeverfahren.
2. Провести методическое исследование и разработать диагностику с чтением, аудированием, письменным и устным выходом; хранить источник и надёжность каждой оценки. Короткий текущий скрининг оставить только ориентиром.
3. Подключить аккаунты и БД; перенести результаты и попытки, внедрить серверные ограничения AI.
4. Реализовать контекстный диалог и проверку артефактов с рубрикой, затем STT/TTS и согласие на обработку аудио.
5. Добавить два полноценных модуля, checkpoints и календарь с нагрузкой по целевой дате. Для ускоренного плана показывать реальный расчёт часов, а не обещание C1 за фиксированный срок.
6. Добавить PWA: версионированный кеш загруженных сессий и карточек, явное состояние offline, очередь синхронизации. AI остаётся онлайн-функцией.

## Визуальный подход

Рабочая тетрадь взрослого студента: тёплый светлый фон, тёмно-зелёный цвет, архитектурная иллюстрация Вены, широкая типографика интерфейса и serif для длинного немецкого текста. Акцент на основной задаче и навыках, без игровой валюты и вымышленных серий посещений.


## Облачное хранилище (реализовано)

Next.js API → Cloudflare D1 REST API. Секреты доступны только серверу. `users` и `sessions` заменяют файловую регистрацию; существующие локальные записи можно перенести отдельным скриптом без смены паролей. Файловая реализация остаётся тестовым/локальным fallback только без конфигурации D1.

`GET/PUT /api/data` изолируют `learning_state` по подтверждённой cookie-сессии. Snapshot включает progress, chat и homework, а revision обеспечивает optimistic concurrency. При конфликте интерфейс не перезаписывает сервер и сохраняет локальную резервную копию. `useCloudLearning` управляет загрузкой, debounce-сохранением, кешем по user_id и сменой аккаунтов. Старые гостевые ключи браузера сохраняются; перенос в пустой аккаунт выполняется явным действием.

Текущие ограничения: snapshot до 1 МБ, история чата до 40 сообщений, синхронизация загружает состояние при входе/фокусе/ручном обновлении; live collaborative editing и автоматическое слияние конфликтов не реализованы. Следующая эволюция — отдельные строки артефактов/попыток и пагинация вместо роста одного JSON-документа.
